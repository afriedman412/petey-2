## What changed, in plain words

**Detect finds a copy whose layout drifted** (33ee91f). Andrew (2026-10-27): "this is the reason we should be using a
model and not rules." Detect (rescan a page) now ends with a pass where the "same kind of box" model picks each of a
block's positions, so a copy set tighter than the others is found ([bm__sd_3856391 BT2-2](http://localhost:5005/#review/bm__sd_3856391/BT2-2),
its address line 12 pt higher). The message names copies found this way ("By the box model"). A copy whose captioned
positions share no word with the template is refused. A block with one field 20 pt wider than the template's now
counts as a copy (an older test changed for it).

**A block's two columns found as one** (33ee91f). The finder joins two repeats whose copies move together, side by
side further apart than its 30 pt reach ([bm__sd_3867602](http://localhost:5005/#review/bm__sd_3867602) p2, each
party's two columns). Suspected since in two "blocks holding two copies" reports (below); not checked, by Andrew's
choice ("let's just keep stockpiling errors").

**"Validate all" on a block type** no longer fails with "no such block" when a block's first position is empty
([lib__i864](http://localhost:5005/#review/lib__i864) BT1, [lib__i9](http://localhost:5005/#review/lib__i9) BT4).

**Run finders no longer crashes** when a block drawn by hand holds some positions of a repeat the finder finds
([bm__sd_497870](http://localhost:5005/#review/bm__sd_497870): "'NoneType' object is not iterable") (9a427eb).

**The structure-error log** (`docs/STRUCTURE_ERRORS.md`). Andrew (2026-10-27): "lets start accumulating these errors
and fixes and see if we can't do something more cohesive when we have them all"; then (stopping a diagnosis): "the
point of the error log is we just collect these instead of fixing them one at a time!" Cases are logged by kind
(blocks missed, blocks holding two copies, grids missed, grids vs blocks, overlapping blocks, groups taking in too
much, groups split apart, fields missing, fields the wrong shape, things made fields that are not), with Andrew's words
and links; a few have diagnoses where he asked. Judgement calls go to `docs/BENCHMARK_JUDGEMENT_QS.md` instead
(questions 10-14: Y / N text boxes, "circle one", office use only, stacked checkbox questions, noise and skew).

**Option groups whose options repeat an answer are split** (a55cacf). Andrew (2026-10-28): "lets fix the overzealous
grouper for good." Most such groups were the publisher's: one radio or checkbox field reused over several questions,
which staging keeps whole ([bm__sd_537564](http://localhost:5005/#review/bm__sd_537564/3) Group2 over every button on
the page; [bm__mu_0bfb2573afdf](http://localhost:5005/#review/bm__mu_0bfb2573afdf/4) a "Yes" column and a "No"
column). One question does not offer the same answer twice: a group in which two options print the same short
caption is cut into its questions, the other options joining the repeated answer on their line or near it. It runs in
the light path on the publisher's groups before the joins and on every group after. Andrew's summary: "instead of
creating a gate around the distance between grouped choices, you created a gate around groups that contain the same
string multiple times." New stagings only; nothing staged or validated was regrouped.

**The light path no longer drops fields with clashing names** (a55cacf). It names fields by place; two option groups in
one block copy or table row got the same name, and the second silently overwrote the first
([bm__mu_0d8e9867024f](http://localhost:5005/#review/bm__mu_0d8e9867024f) p3: 14 of 20 YES / NO fields gone). A name
already taken now falls back to the next plain one. Not the same bug as the earlier rename-collision fixes, which are
about renames, not about building a blueprint.

**64 benchmark forms re-staged** with that fix: the forms short of the fields staging had found that Andrew had not
opened (no verdicts, no draft; their finder grid / block records had nothing of his). Old copies and records are in
`runs/benchmark/before_restage_2026-10-29/`. Their finder grids and blocks are gone until finders run again. The 8
short forms with his work on them were left.
