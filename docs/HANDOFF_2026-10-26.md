## What changed today, in plain words

**Duplicates archived.** One copy per form: the most recently validated copy of each blank kept, 237 others moved to
`runs/retired_dups_2026-10-26/` (manifest + `archive_dups.py`; nothing deleted). The review page lists 518 blueprints.
Three blanks still have two copies, none validated: cra-t1-on, da4187, i9 / i_9.

**Every field on the kept copies has parts** (`x_petey_identifiers`), and all but 10 print their name (the 10 are
rename clashes, e.g. je__acord_140 `fire_district_name`). Written by `eval/naming_apply_2026_10_26.py` in three
passes (default: parts + 3,165 renames; `--reread`: 309; `--context`: 66 renames + 2,859 block parts); before-copies
and rename lists in `runs/naming_2026-10-26/`. Verdicts followed; every validated form stayed validated.

**Grids are read by identifiers** (Andrew: "a unique identifier for each row/column from the existing data"). A row's
identifier is what its cells share and no other row has (a number, a letter step, or words); which way the grid lies
does not matter. On the 701 active grids against the old string reading: the code check passes 42 more, fails one
more (lib__gse_1084 p2-G1, a real miss); standardize stopped 37 kinds of wrong proposals. Standardize only changes
words on the person's pick. The finder (which layouts are grids, `iterated` / `aside`) is still name-based, by
decision (it would add ~300 small two-entity pairs and drop 139 grids).

**One parts reader.** `naming.read_name(name, spec, block, line, keyed, part)` reads a name in the standard's order;
`field_identifiers.context` / `read_parts` give it the form's context (block records, grid lines, names alike but
for a number, compound-value parts). A number inside a name read with no context stays in the subject
(`all_12_months` is never a block number). The old-order reader is deleted.
